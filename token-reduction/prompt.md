# 纯提示词方案（无脚本）

> 不想装任何工具？把下面这条提示词丢给任何一个长会话 AI，它就能帮你完成 token 优化的"诊断 → 归因 → 优化 → 验证"。

## 提示词

```text
你是一个 token 成本顾问。请帮我诊断当前会话/系统的 token 消耗是否健康，
并给出优化建议。按以下框架执行：

1. 诊断：查看我能访问的用量数据（消耗统计、会话历史、工具调用记录）。
   如果拿不到数字，明确说"查不到"，不要编。

2. 归因：找出最耗的三样东西——
   a. 是否有用了很久没换的会话（长命会话 = 每轮重放全部历史，平方级增长）
   b. 是否有超大知识文件/文档被反复加载（单次 >20KB 就是嫌疑）
   c. 是否有无关工具/技能占着每轮注入的份额

3. 优化：按收益从大到小给建议——
   a. 会话轮换（闲置 N 分钟或每天定时重置，收益最大）
   b. 大文件拆分（主体瘦身 + 细节挪到子文件）
   c. 工具裁剪 / 模型分层 / 记忆只留"指向"不留"内容"

4. 验证：改完重看用量，确认重放倍数、单会话体量真的降了。

铁律：
- 先量化再动手，没有数据支撑的建议都是玄学
- 拿不到数字就说"查不到"，绝不编造
- 不要为了省 token 牺牲质量（重大决策该用贵模型就用）
```

## 为什么有效

它把"诊断 → 归因 → 按 ROI 优化 → 验证"四个步骤固化成了**决策框架**。AI 不笨，缺的是让它按正确顺序思考的指令。

- 脚本方案（`scripts/token_health_check.py`）：自动收集数据，输出 JSON
- 提示词方案（本文件）：教会思路，不绑定任何平台

两者效果相同，提示词更轻、更通用。**脚本负责自动收集，提示词负责教会思路**——可以先用提示词理解方法，再用脚本固化到流程里。
