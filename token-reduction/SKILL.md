# Token 缩减（诊断→归因→优化→验证）

> 系统性缩减 LLM Agent 的 token 消耗。**先量化归因，再按 ROI 执行，最后验证回读。**
> 零配置：脚本自动收集数据，自动判断执行。适配任何基于长会话 + 工具调用的 Agent 架构。

## When to Use

- 用户问"token 消耗太高怎么办 / 缩减成本 / 优化 token"
- 定期（月/周）token 成本复盘
- 新模型/新配置切换后检查消耗

## 核心认知

**Token 消耗的真相**（实测 30 天 7.1 亿 token 归因）：

| 根因 | 权重 | 机制 |
|------|:---:|------|
| 长命会话不换新 | ~96% | 一个会话用 7 天，每轮重放全部历史 → O(N²) 放大 |
| 工具输出巨大 | 82% 上下文 | 大 skill 加载/大文件读取/搜索大结果 |
| Compaction 隐形成本 | 高 | 消息被大量压缩，每次压缩 = 一次昂贵全量重读 |
| 工具 schema 过大 | 每轮注入 | 无关工具全量注入 |
| 记忆模板残留 | 每轮注入 | 复制 profile 时记忆没定制 |

**一句话**：真元凶是"一个 session 用 7 天不换"——工具输出大只有长命会话才变成 50 倍重放。

## 工作流（自动执行）

### 第 1 步：诊断（数据归脚本）

```bash
python3 scripts/token_health_check.py --days 30
```

输出 JSON：
- `insights`：input/output/total token、成本、重放倍数（total/input）
- `top_sessions`：最肥会话（历时/字符/消息数）
- `top_tools`：工具输出排行（调用/字符/单条最大）
- `big_skills`：>20KB 的知识文件列表
- `session_reset`：会话轮换配置是否已设

### 第 2 步：归因（判断归 Agent）

- 重放倍数 = total/input；>20x = 长命会话放大
- 单会话 >3 天 / >3000 消息 = 元凶
- 单条 tool 输出 >30KB = 大文件/大 skill 加载
- input/output 比 >5:1 = 工具输出/重读是燃料

### 第 3 步：优化（按 ROI 自动执行）

**P0-1 会话自动轮换**（收益 70-90%）：
```yaml
session_reset:
  mode: both          # none/idle/daily/both（先到先重置）
  idle_minutes: 240   # N 分钟无消息自动重置
  at_hour: 4          # 每天固定时刻重置
```
- 重置前 Agent 有 1 轮机会保存关键记忆
- ⚠️ 配置命令报 "not recognized" 可能是误警——查官方 schema/文档确认是合法键再改

**P0-2 大知识文件拆分**（单次加载降 80%+）：
1. 备份 `.bak.YYYYMMDD`
2. 主体瘦身：保留"触发+铁律+工作流+指针"，细节迁 `references/*.md`
3. 验证：references 指针全部有效
- 实测：121KB → 9.3KB（-92%），单次加载 40K token → 5K

**P1-1 工具集裁剪**（schema 注入 -43%）：
按你的平台工具管理语法，禁用与任务无关的工具，只留必要集。
示例：保留 终端/文件读写/代码执行/知识检索/记忆 类，禁用 多媒体生成/演示/辅助 类。
工具越少，每轮注入的 schema 越小。

**P1-2 模型分层**：高频例行任务用轻量模型，决策/审计用重量模型。

**P1-3 记忆系统**：事实进数据源，记忆只留"指向"；职责专属化（禁模板残留）。

**P1-4 知识文件单一数据源**：子节点软链指向权威源，改一处处处生效。

**P2-1 峰谷调度**：可延迟的定时任务挪出模型计价峰值时段。

**P2-2 前缀缓存**：不改动过去上下文/不中途换工具集 → 保缓存命中。

### 第 4 步：验证（回读确认）

- 重跑体检脚本看指标改善
- 大文件拆分后单次加载字节数
- 配置生效需新会话 / 网关重启
- 记录优化前后对比

## 坑

1. **数据源唯一**：insights 是权威，内部状态库的 token 字段可能大量为空，不能直接求和
2. **配置改完不立即生效**：会话轮换需网关重启；工具裁剪只影响新会话
3. **备份先行**：任何拆分/重写前留 .bak，可回滚
4. **大文件判定阈值 20KB**：超过就拆，别等它长到 100KB
5. **不要为省 token 牺牲质量**：审计/重大决策保留重量模型
6. **先量化再动手**——不量化就优化都是玄学

## 支撑文件

- `scripts/token_health_check.py` — 数据收集脚本（零配置自动探测，输出 JSON）
- `prompt.md` — 纯提示词方案（无脚本，丢给任何长会话 AI 即可用同一套方法论）
